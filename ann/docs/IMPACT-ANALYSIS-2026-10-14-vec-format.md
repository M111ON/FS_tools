**สถานะ:** วิเคราะห์ผลกระทบ (ยังไม่ทำ) · รอ confirm
**คำถามที่ตอบ:** ทำแล้วกระทบอะไร ใช้เวลานานไหม

## 1. ผลกระทบ — กระทบ 3 ด้าน

### 1.1 ดิสก์: ดีขึ้น 201 MB
| | ตอนนี้ | หลัง f16 |
|---|---|---|
| `ann_index.jsonl` | 247.0 MB | **46.1 MB** |
| ดิสก์ว่าง | 6.8 GB | **~7.0 GB** |

*(ไม่คืนพื้นที่มากเท่าที่คิด เพราะ index โตต่อเนื่อง — แต่อัตราการโตช้าลง 5.4 เท่า)*

### 1.2 ความเร็ว: **ไม่เปลี่ยน** (สำคัญ)
วัดจริงแล้ว แยกได้ชัด:
```
query ผ่านข้อความ = 29ms  (embed 27ms + scan 2ms)
query ส่ง vec ตรง   =  2ms  (scan อย่างเดียว)
```
- **scan = 2ms เท่านั้น** — และ `LZEntry.vec` เป็น `float *vec` (float32 ใน RAM) อยู่แล้ว
- f16 บนดิสก์ถูก decode เป็น float32 **ตอน boot ครั้งเดียว** → dot product ยังเป็น float32
- **สรุป: latency เท่าเดิม** (ต่างกันไม่ถึง 1ms จาก load ที่เร็วขึ้น)

### 1.3 ความแม่น: หาย 0.09%
| | recall@10 |
|---|---|
| ตอนนี้ (text) | 0.9999 |
| f16 | 0.9991 |
| หาย | **0.0008 = 0.08%** |

→ ทุก 1,000 คำถาม เพี้ยน 1 คำถาม (แต่ยังได้ top-1 ถูก 99.3%)

### 1.4 ความเสี่ยง: จุดที่ต้องระวัง
| ความเสี่ยง | ระดับ | กันยังไง |
|---|---|---|
| server อ่าน binary ไม่ได้ (โค้ดเดิม text) | **สูง** | เขียน decoder + คง text fallback |
| bench tools พัง (อ่านไฟล์ตรง 4 ตัว) | กลาง | อัปเดตพร้อมกัน |
| `ann_sync` สร้างผิด format | กลาง | แก้ให้ตรง + test |
| ann/kv ผสมกัน | **ต่ำ** | ตรวจแล้วไม่ปน (kv_ เป็นแค่คอมเมนต์) |
| index เสียหายระหว่างแปลง | กลาง | **สำรองก่อน + คง text ไว้** |

## 3. สิ่งที่ต้องระวังเป็นพิเศษ (ตามที่คุณสั่ง)

### 3.1 "อย่าเอา ann กับ kv มาผสมกัน"
ตรวจแล้ว **ไม่ปนกัน**:
- `data/memcore/` มีแต่ `ann_*` (ann_index.jsonl, ann_anchors.bin, ann_index.order)
- `kv_` ใน `ann_search.c` = **คอมเมนต์ 4 จุด** (อธิบายว่าทำไม *ไม่* ใช้ชื่อ kv_)
- kv_* ที่เหลือใน DWGLS `build/` = คนละโปรเจกต์ ไม่แตะ

→ งานนี้ทำใน `I:/tools/ann` เท่านั้น **ไม่แตะ KV เลย**

### 3.2 "เช็คให้รอบคอบว่าไม่มีอะไรหาย"
**มีของหาย 0.09%** — ต้องพูดให้ชัด ไม่ใช่ "ไม่หาย"
- ถ้าต้อง **ไม่หายเลย** → ต้องใช้ **float32** (92 MB, ยังประหยัด 155 MB)
- ถ้ายอมรับ **0.09%** ได้ → **f16** (46 MB, ประหยัด 201 MB)

## 4. ทางเลือกสุดท้าย (ตัวเลขจริง)

| | ขนาด | ประหยัด | recall@10 | เวลาทำ |
|---|---|---|---|---|
| อยู่เฉยๆ | 247 MB | 0 | 0.9999 | 0 |
| **f32** | 92 MB | 155 MB | **1.0000 (ไม่หาย)** | 1.5–2 ชม. |
| **f16** | **46 MB** | **201 MB** | 0.9991 (หาย 0.09%) | 1.5–2 ชม. |
| int8 | 23 MB | 224 MB | 0.9909 (หาย 0.9%) | 1.5–2 ชม. |

**หมายเหตุ:** ทั้ง 3 ทางใช้เวลาเท่ากัน (งานโค้ดชุดเดียวกัน) ต่างแค่ 1 บรรทัดตอน encode

## 5. แผนสำรอง (ถ้าอยากปลอดภัยสุด)

ทำ **f32 ก่อน** (ไม่หายเลย) → วัดจริง → ถ้าอยากเล็กลงอีกค่อยขยับเป็น f16
เพราะโค้ดชุดเดียวกัน แค่เปลี่ยน 1 บรรทัด → **ทำ f32 ก่อนได้ความมั่นใจ แล้วค่อยเลือก**
