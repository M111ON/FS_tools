# ANN query log — one line per search (built 2026-10-29)

**Why it exists:** an answer that cannot be dated and addressed is unprovable a week later.
Yesterday's audit found 867 memories whose source session no longer exists — nothing recorded
*which* session a fact came from, so the loss could only be measured, never explained. The query
log is the same lesson applied to ANN: every search leaves one line with its clock, its input
hash, the index identity, what the walk touched, and — when the caller knows it — the chat
coordinate it came from.

## Where and what

```
I:\tools\ann\data\query_log\ann_query-YYYYMMDD.jsonl     (rotates at local midnight)
```

Sibling of `data/memcore/`, never inside it: the index is immutable and swapped atomically, the
log is append-only and grows daily. One must never be able to damage the other, and a regrow
never touches the log.

One object per completed search:

```json
{"v":1,"ts_ms":1793208113380,"coord":"ses_gate_0998#4","input_kind":"vec",
 "input_hash":"fnv:0cbfb0dc","input_chars":0,"dim":384,"topk":3,"K":64,
 "index_fp":"1793106246-263336994","n_cand":63915,"items_scored":13538,"budget":25566,
 "truncated":0,"fallback":0,"roster":0,"walk_hash":0,
 "top":[{"sid":"a9ad0c1e…","score":1.0000,"rank":1}],"latency_us":12760,
 "mode":"search","batch":0,"scope":null,"sid_filter":null,"model_hash":null}
```

| field | meaning | why it is not optional |
|---|---|---|
| `v` | format version | the log outlives the code that wrote it |
| `ts_ms` | **request clock** | never an ingest time — an ingest time makes every old query look new |
| `coord` | `sid#ordinal` or `null` | `null` is allowed, **absent is not**: a missing field hides the gap, `null` reports it |
| `input_kind`/`input_hash`/`input_chars` | what was asked | text → fnv of the string; vec → fnv of the float bytes (never `0`) |
| `index_fp` | `mtime-size` of the index file | ties the answer to the exact index that produced it |
| `n_cand`, `items_scored`, `budget`, `truncated`, `fallback`, `roster`, `K` | what the walk actually did | an answer without its walk cost cannot be compared later |
| `top[]` | ids + scores (≤5) | enough to reconstruct the verdict, small enough to keep |
| `latency_us` | wall time of the request | measured, not estimated |
| `mode`/`batch` | single vs batch request | a batch line is not a user query |
| `model_hash` | currently `null` | the embedder is an external sidecar and exposes no identity; recorded as null rather than faked |

**No `recall@5`.** Recall needs an oracle, and the server has none — that number belongs to the
bench receipts (`sift*_receipts.jsonl`). A log that prints a metric it cannot measure is the exact
failure mode this project keeps paying for.

## How it is written (and what it costs)

`memcpy` into a 128-line ring buffer inside the existing request lock; the file is written at most
once per second, or when the buffer fills. A crash loses at most 128 lines of observability —
never a result. `atexit(qlog_flush)` keeps the tail on a clean stop.

| gate | result (measured 2026-10-29) |
|---|---|
| completeness | 1000 queries → **1000 lines**, `dropped: 0` |
| validity | 1000/1000 lines parse as JSON |
| coord honesty | 500 lines `coord:null` / 500 with a coordinate — exactly what the caller sent |
| logging off | `ANN_QUERY_LOG=0` → **0 lines written** |
| latency cost | same binary, same 1000 queries: **p99 34,829 µs off vs 34,817 µs on**, mean 13,151 vs 12,968 — **ON ≈ OFF**. The 1.4% lower mean on the ON run is benchmark noise, NOT logging being faster; the honest reading is "no measurable cost" |
| rotation | file is `ann_query-20261029.jsonl`; midnight creates the next day's file |
| flush on demand | `GET /v1/qlog/flush` → `{"flushed":N,"dropped":M}` |

Reproduce: `python bench_qlog.py 8097 1000` (needs the server started with
`ANN_INDEX_PATH/ANN_ANCH_PATH/ANN_ORDER_PATH` pointing at `data/memcore/`, because the default
paths are relative and a second instance will otherwise load zero entries).

## Consumers

`chatmap.py when <term>` reads these files as its **8th layer**, so a coordinate answered with
"here is what was said" can also answer "and which queries consumed it":

```
$ chatmap.py when 0.9627
layers: time=10 | vault=0 | fact=2 | commit=16 | artifact=0 | doc=3 | block=4 | querylog=2
  query 2026-10-29 00:24  ses_e9aaa4b41ffeHZ4Farueanw7PW#386  query 12708 us · top1 1.0000 …
```

That is the whole loop, end to end: message → fact → commit → query that used it.

The log files are scanned without a date filter — a query run today can cite a message from any
month, so the file's own day says nothing about which coordinate it may contain — bounded at 400
files, and the count is reported in the layer's `why`.

## Deploying a server change here (learned the hard way)

The live service is NOT started from `build/ann_search.exe`: `ann_keepalive.py` prefers
`build/ann_search_batch.exe` when it exists (falling back to `ann_search.exe`). So after `make`:

```
copy build\ann_search.exe build\ann_search_batch.exe     # backup the old one first
# keepalive only ever STARTS, never kills a healthy server -> restart is manual:
Stop-Process -Name ann_search_batch -Force
python ann_keepalive.py --once
```

Skip the copy and the running service keeps executing the old binary while `make` reports success.
Restart costs ~30 s (index reload). If both a manual start and the scheduled `ann-keepalive` task
fire, two instances appear — check `Get-Process ann_search_batch` and keep one.

Verified after deploy 2026-10-29 00:31: entries 63,915, `embed: ok`, and a real text query with
`coord` landed in `data/query_log/ann_query-20261029.jsonl` (top scores 0.8848/0.8841/0.8826 —
real neighbours, not the tautology).

## Who may call the flush endpoint (added 2026-10-29 after review)

`/v1/qlog/flush` is the only state-changing verb on a server that binds `INADDR_ANY`, so it is
gated. Two accepted proofs:

1. header `X-Admin-Token: <ANN_ADMIN_TOKEN>` — when the env var is set, **the header is required**,
   even from loopback;
2. env unset **and** the peer is on `127.0.0.0/8` (a local tool or a bench).

Everything else → `403 {"status":"error","error":"forbidden","detail":…}`, never a silent success.
The comparison walks every byte instead of returning at the first mismatch. Without this, anyone on
the LAN could call flush in a loop and turn the log into a disk-write amplifier.

Measured (2026-10-29, binary in `build/ann_search_batch.exe`):

| case | result |
|---|---|
| loopback, no token configured | **200** `"auth":"loopback"` |
| via LAN IP `172.30.192.1:8096`, no token | **403** |
| token configured, no header | **403** |
| token configured, wrong header | **403** |
| token configured, correct header | **200** `"auth":"token"` |

## Single instance

Two guards, because they answer different questions:

- **`SO_EXCLUSIVEADDRUSE`** (pre-existing, STRESS-REPORT #8) — a second bind fails loudly. Verified
  with a real duplicate: it loaded 63,915 rows, then printed `bind 8096 failed (already in use?)`
  and exited. No split-brain — but ~30 s of wasted load, and for those 30 s `ps` shows two servers.
- **pre-bind connect probe** (added 2026-10-29) — before loading anything, connect to
  `127.0.0.1:<port>`; if it accepts, exit 0 immediately. Measured: duplicate now exits in **57 ms**
  with `port 8096 already accepting -> another instance holds it`.

## No circularity with `when`

`chatmap.py when` **never calls the ANN server** — it opens SQLite and reads
`ann_query-*.jsonl` as files (verified: no `urllib`/`socket`/`8096` reference in `chatmap.py`).
So a `when` invocation cannot log itself, and the querylog layer cannot feed on its own output.

Rule for the future: if a tool ever does query ANN *from* a `when` result, it must set
`mode:"when"` in the request so the log distinguishes a provenance probe from a user search.
`mode` is already a field for exactly this reason.

## Honest limits

- `model_hash` is null: the embedder is a sidecar with no identity endpoint.
- An exact `top1 == 1.0000` is usually the caller sending a row's own vector; `when` flags it as
  `querylog_top1_exact` instead of pretending it is a neighbour.
- The log records searches, not embeddings or regrows. A query that fails before the walk
  (bad body, embed unavailable) writes no line — failures are counted by the caller, not here.
- Lines are capped at 768 bytes; a request that would exceed it is dropped and counted in
  `dropped` rather than written truncated (a truncated JSON line is worse than a missing count).

## Cost of the feature in code

`ann_search.c`: ~150 lines (ring buffer + flush + one call inside `handle_search`), plus the
`GET /v1/qlog/flush` endpoint. Nothing else in the server changed; `ANN_QUERY_LOG=0` is a hard
off switch.

One bug worth recording: the first version passed `char top_sid[32][64]` as `const char * const *`
and segfaulted inside `lz_json_escape` — element `i` was read as a pointer out of the row bytes.
The parameter must be `const char (*top_sid)[64]`. Found with gdb, fixed, re-gated.
